## 首版部署架构

默认方案：单台 Linux 主机、Docker Compose、预置账号受限使用。MySQL 继续保存身份、对话和运行记录，不分库；MinIO 保存文件和解析结果。首版不引入多机调度、RabbitMQ 或未实现的恢复 Worker。主机故障会影响全部服务，外部备份与恢复演练必须完成；容量依据目标负载测量，不预先声称高可用或某个并发数。

```text
用户浏览器
    │ HTTPS :443
    ▼
Nginx ──► Web / Next.js BFF ──► FastAPI
                                 ├──► MySQL（身份、对话、运行、上下文）
                                 ├──► MinIO（私有文件、解析结果）
                                 ├──► 模型 Provider（允许的出站调用）
                                 └──► Unix Socket ──► Office 执行器
                                                          └──► 临时无网络解析容器
```

公网域名只指向 Nginx。HTTP :80 仅用于跳转到 HTTPS 或证书验证；SSH 仅向管理来源开放。普通浏览器只访问同域 Web 和 `/api/nexus/*`，不提供公网 FastAPI、MySQL、MinIO 或 Office 入口。能够打开登录页不等于有权读取聊天；验收以实际数据响应为准。

### 组件与运行方式

| 组件 | 首版运行方式 | 网络及持久数据 |
|---|---|---|
| Nginx | 独立容器，负责证书、Host 校验、HTTPS、限流和流式转发 | 唯一发布 80/443；连接 Web，不能连接数据库网络 |
| Web | 拟新增生产镜像，执行现有生产 build/start 脚本 | 不发布 3000；只持有部署 Key，不持有内部 Key／Provider／数据库凭据 |
| API | 使用现有 API 镜像作为基础，补运行用户和权限检查 | 不发布 8000；连接 Web、数据库、MinIO和允许的 Provider 出站网络 |
| MySQL | 独立容器，运行账号和迁移账号分开 | 不发布 3306；专用持久卷，限制普通应用账号的数据库权限 |
| MinIO | 独立容器，私有 bucket；API 使用限定 bucket 的账号 | 不发布 9000/9001；专用数据卷，管理凭据只用于运维 |
| Office 执行器 | 主机服务，由管理员控制，构建／检查镜像后启动 | 仅暴露受限 Unix Socket；API 不挂载 Docker Socket |
| 文件清理／备份 | 由管理员配置定时任务并记录失败 | 调用现有精确对象键清理命令；不是模型执行 Worker |

Compose 拟划分入口、Web→API、API→数据网络；数据库／存储网络使用内部网络，API 单独保留 Provider 出站连通性。不能把所有 API 网络设为禁止外连后期待模型调用正常。服务间使用 Compose 服务名，避免绑定临时容器 IP。网络原理依据 [Docker Compose Networking](https://docs.docker.com/compose/how-tos/networking/)。

`internal: true`、未发布端口和防火墙共同组成部署检查；仍需核实 Docker 端口转发、IPv4／IPv6、主机管理来源和实际外部可达性。运维访问数据库／MinIO 管理端优先使用受控 SSH 隧道或临时受限管理入口，不永久公开管理端。

### 配置和秘密

- 首版使用服务器上受限的环境文件注入现有 Settings；Web、API、数据库和存储分别配置，不复制所有秘密到每个服务。配置文件不入 Git、不进镜像构建上下文、不通过 `NEXT_PUBLIC_` 暴露。
- API 明确设置 production、开启登录、Secure Cookie、正式 HTTPS Origin、独立部署 Key／内部 Key／游标签名 Key／Provider 续接加密 Key，另提供数据库和 MinIO 连接凭据。Provider API Key 继续留在 API 配置，Base URL 继续从数据库读取。
- Web 只设置服务端 `NEXUSPILOT_API_URL`（内部 API 服务地址）及匹配的部署 Key。Nginx 确保证书终止后传给 Web 的 Host／协议语义与现有 Origin 比较一致；只信任已配置代理来源，覆盖外部自报转发头。
- Compose 可以引用秘密文件，但当前 API Settings 没有对应的文件读取配置；采用 Docker secrets 时需实现文件到应用配置的读取，不能只挂载后声称应用已使用。[Docker Compose Secrets](https://docs.docker.com/compose/how-tos/use-secrets/)说明挂载文件及按服务授权的机制。
- 用户密码用现有终端预置命令交互输入，不写在命令参数、Compose 或聊天中。服务 Key 与用户会话承担不同验证职责，网络隔离不能替代用户授权。
- MySQL／MinIO 初始化环境变量不应被当作既有数据卷的密码轮换方案；存量服务需按实际账号管理流程变更并验证，不能删除数据卷“重新初始化”。

### 流式请求和 Office

Nginx 的 SSE 路径需要关闭响应缓冲和缓存，并验证增量文字即时到达；读取超时按最长允许模型／工作流请求设置。Office 的 API 等待上限与解析超时也须纳入入口配置。不能在超时后自动重发模型 POST，避免重复生成和费用。代理缓冲语义依据 [Nginx proxy_buffering](https://nginx.org/en/docs/http/ngx_http_proxy_module.html#proxy_buffering)。

Office 主机服务采用现有 Unix Socket 协议。API 仅挂载 Socket 专用目录，设置一致的用户／组权限，不加入 Docker 管理组；执行器有启动解析容器的高权限，需要专用账号和管理员管理。更新镜像后重启执行器以固定新版本。上线前按目标 CPU、Linux 内核、cgroup 和安全模块运行[阶段7验收](phase-7-tool-runtime-plan.md#linux-云服务器兼容与验收)。此前 macOS Docker Desktop 的结果不能替代云服务器验收。

未通过时暂不开放 Office；文本／支持的 PDF 能力仍须独立验证。OCR、复杂图表、大文件及模型自主工具继续后置。当前同步工作流不能保证浏览器断开或服务重启后完成，首版需明确中断状态和重试行为。

### 数据、运维和恢复

- MySQL、MinIO、证书和日志使用独立持久位置；发布镜像更新不删除数据卷。镜像按发布版本固定，不以不确定的 `latest` 作为回退依据。
- 先确定空库上线还是迁移本地数据。若迁移历史会话，核对原 owner 与正式账号的对应关系；不能自动把所有本地数据转给任意新账号。
- 数据库、MinIO 对象和对应元数据备份必须能一起恢复；备份放到主机之外并限制访问，演练实际恢复。保留时间和允许的数据损失／停机时间由实际使用要求确认。
- 记录启动失败、认证拒绝、模型错误、磁盘和备份／文件清理失败；不记录 Cookie、密码、完整服务凭据或默认导出全部聊天正文。配置日志轮转，避免磁盘被填满。
- 发布前保存数据库备份与上一版镜像。应用回退只在数据库兼容时使用旧镜像；不自动执行破坏性降级、不删除上传对象。长请求在升级前需等待结束或明确告知中断，不能用容器重启冒充任务恢复。

- [ ] 明确个人私用、受限内测或公开多用户范围。关闭登录的固定 owner 模式只能用于可信本机，不能直接公网开放。

## 部署执行顺序

1. 修复 JSON 鉴权绕过、补默认值拒绝检查；保留失败用例并要求回归通过。随后检查、验证并固定发布提交与镜像版本，避免部署当前未提交工作区。
2. 按上述设计实现生产 Compose、Web 镜像、Nginx 和分服务配置模板。用 `docker compose config --quiet` 检查配置，避免打印替换后的秘密；再构建和运行隔离测试。该命令的检查模式依据 [Docker Compose Config](https://docs.docker.com/reference/cli/docker/compose/config/)。
3. 确认主机操作系统／架构、SSH、域名、使用范围及数据迁移方案，准备持久卷、受限网络、备份位置和服务凭据。
4. 启动 MySQL、MinIO，验证健康和应用账号权限；先执行备份，再以一次性迁移步骤升级到当次发布要求的 revision（当前最新 `20261008_0023`）。API 日常启动不自动执行未经检查的迁移；失败则停止发布。
5. 通过可信终端预置首个登录账号，核对模型登记、能力目录及 Provider endpoint。启动 API 和 Web，先经受限入口验证登录、普通对话、会话归属与文件功能。
6. 构建并检查目标架构的 Office 镜像，配置主机执行器和 Socket，通过验收后启用。配置精确文件清理、备份、日志轮转与基本告警。
7. 配置正式域名、HTTPS、入口限流和主机／云网络规则，完成下方的外部安全与业务验收。真实 Provider 冒烟使用事先确认的模型及受限调用范围。
8. 验收通过后开放到确认的使用人群，记录发布版本、配置位置、备份与回退操作；失败时保持入口受限，修复后复测。
