# NexusPilot LLM Platform 总体规划

**文档日期：** 2026 年 7 月 29 日
**文档状态：** 当前总体规划（权威入口）
**适用范围：** 平台后端、Worker、模型适配、工具执行、Agent 协作和可观测性

## 目标

- 要实现的结果：建设一个能够统一调用多家模型、可靠执行异步任务、受控调用工具、保存执行证据并对重要结果独立审核的 LLM 运行平台。
- 要实现的结果：为后续 Web 或其他业务应用提供稳定 API，但不在平台核心尚未稳定时提前建设个人超级 App。
- 明确不处理：默认多模型投票、自训练模型路由器、自定义 MySQL LangGraph Checkpointer、Temporal、全仓库向量检索和无人确认的生产发布。

## 文档治理

- 本文是阶段顺序、当前状态和完成门禁的唯一总体入口。
- `docs/implementation/phase-*.md` 负责对应阶段的详细实施事实与验证证据，不重新定义总体阶段。
- README 只提供运行入口和当前能力摘要，不作为需求依据。
- 原始方案中“第一阶段验收条件”同时包含 RabbitMQ、工具、Agent 与 OpenTelemetry，实际属于全平台累计验收；本文已按可独立验证的阶段重新划分。
- 代码、测试与迁移事实和本文冲突时，先判断实现错误或文档过期，再更新唯一当前描述，不保留平行版本。

## 总体结构

```text
业务调用方 / 后续 Web
          │ HTTP / SSE
          ▼
FastAPI Controller
          │
          ├── 同步模型请求 ──► ModelProvider adapters
          │
          └── 异步任务事务 ──► MySQL task + outbox
                                      │
                                      ▼
                              RabbitMQ publisher
                                      │
                                      ▼
                                  Worker
                                      │
                    ┌─────────────────┼─────────────────┐
                    ▼                 ▼                 ▼
                模型服务          工具执行服务       代码搜索/MCP
                    │                 │                 │
                    └─────────────────┴─────────────────┘
                                      │
                                      ▼
                           MySQL + MinIO 执行证据
```

MySQL 保存平台业务事实；MinIO 保存大型输入输出；RabbitMQ 只传递最小任务通知；OpenTelemetry 后续提供跨进程诊断，但不取代业务状态。

| 2. 多供应商模型接口 | 统一请求响应、四家适配器、SSE、重试、费用和原始证据 | 已完成 | Provider/HTTP/SSE/持久化测试通过 |

| 3. RabbitMQ 任务执行 | 事务 outbox、可靠发布、Worker、幂等消费、重试和死信 | 待评审 | 故障窗口测试通过；无消息丢失或重复副作用 |

## 质量原则

1. 正确性和可恢复性优先于功能数量与开发速度。
2. 每个阶段先定义故障模型、幂等边界和验收测试，再实现外部依赖。
3. 供应商、消息中间件和工具协议必须位于适配层，业务服务不直接依赖厂商 SDK。
4. HTTP Controller 只处理协议和输入输出；Service 处理业务规则；ORM Model 与 HTTP Schema 分离。
5. MySQL 是任务状态、费用、错误和结果的权威来源；消息和追踪不能成为唯一事实。
6. 至少一次投递意味着业务必须幂等，不能把 RabbitMQ 的确认当成恰好一次执行。
7. 任何外部副作用必须有稳定幂等键、超时、有限重试和可查询结果。
8. 程序测试和确定性验证优先于模型自评；重要结果才使用独立审核模型。
9. 代码修改必须在隔离工作目录执行；只读任务与写任务使用不同权限。
10. 未通过阶段门禁时不开始下一阶段，禁止用空实现或只建目录表示“完成”。

## 通用完成标准

每个阶段标记完成前必须同时满足：

- 行为、错误、重试、取消和恢复路径均有明确契约。
- 新增或实质修改函数有准确说明注释。
- 定向单元测试、集成测试、静态检查和数据库迁移检查通过。
- 外部依赖不可用时能够安全失败，不产生无法解释的中间状态。
- API Key、凭据和敏感内容不进入普通日志、消息或公开错误。
- 当前文档、环境示例和运行命令与代码一致。
- 未执行的真实基础设施或供应商验证明确标记 `NOT_RUN`。
