# NexusPilot LLM Platform 总体规划

**文档日期：** 2026 年 9 月 2 日
**文档状态：** 当前总体规划（权威入口）
**当前实施焦点：** 阶段1～3已完成；阶段4前端与阶段5身份认证正在实施；阶段10已因 Agent Workflow 独立后台执行的真实需求恢复规划但尚未开始编码；阶段5后续凭据、阶段6可观测性、阶段7工具、阶段8代码搜索和阶段9 MCP 的既定边界保持不变

## 目标

- 建设一个具有稳定数据底座、可独立复用 LLM 核心能力、可靠异步执行和受控 Agent 工作流的平台。
- 为后续 Web 或其他业务应用提供可查询、可恢复、可审计的 API，而不是只打通一条 Agent 演示流程。
- MySQL 保存业务事实；MinIO 保存大型内容；消息队列负责通知和调度，不成为唯一状态源。
- 默认多模型投票、自训练模型路由器、Temporal、自定义 MySQL LangGraph Checkpointer和无人确认的生产发布不在当前范围。

## 文档治理

- 本文是阶段顺序、状态和完成门禁的唯一总体入口。
- `docs/implementation/phase-*.md` 记录对应阶段的详细规划、实施事实和验证证据。
- README 只提供运行入口和当前能力摘要，不作为完成状态依据。
- 一个阶段只有在其完整能力和查询闭环通过验收后才能标记“已完成”；只有表、POST 接口或目录不能代表完成。
- 代码、测试和迁移与文档冲突时，必须更新唯一当前描述，不保留两个互相冲突的路线图。

## 排序原则

- 阶段编号表达当前交付顺序，不再保留因历史规划形成的空档或倒序。
- 已实现能力排在前面：数据与控制平面、LLM 核心能力、Agent 工作流依次为阶段1～3。
- 当前优先完成“服务可用闭环”：阶段4 Web 内部产品面、阶段5最终用户身份与凭据、阶段6可观测性。
- 代码执行与外部扩展后置：阶段7工具、阶段8代码搜索、阶段9 MCP 必须建立在稳定服务、授权和诊断能力之上。

## 总体结构

```text
受信业务调用方 / Web
          │
          ▼
身份、授权与凭据层
登录会话 / 当前主体 / 个人 API Key / 供应商凭据
          │
          ▼
API 与控制平面
用户、会话、消息、运行、任务、调用、产物、审计查询
          │
          ▼
LLM 核心能力层
Model Gateway / Context / Prompt / Model Catalog / Evaluation
          │
          ├── Memory（仅规划和实验性管理能力，不进入 Responses）
          └── Knowledge（独立知识库，后续另行规划）
          │
          ▼
Agent 与服务交付层
Agent Workflow / Web / Identity / Observability
          │
          ▼
后续代码能力层
Tool Runtime / Code Search / MCP
          │
          ▼
按需可靠执行层
Transactional Outbox / RabbitMQ / Worker / Idempotency
          │
          ▼
MySQL + MinIO + OpenTelemetry
```

Agent 只组合稳定的基础单元，不自行重复实现会话历史、记忆检索、上下文裁剪、知识读取或模型调用。

## 阶段顺序与依赖关系

- 阶段1解决“数据是否可管理、可查询、可组合事务、可追溯”。
- 阶段2解决“LLM 能力是否可以作为独立模块使用”。
- 阶段3在阶段1、2之上交付可独立使用的 `model_only_v1` 同步工作流；工具节点、Implementer 和代码修改仍明确不可用。
- 阶段4～6优先解决服务是否可被人使用、是否具备最终用户安全边界、是否能够运维诊断。阶段7～9才扩展代码工具、语义搜索和外部 MCP 能力。
- 阶段10解决可靠异步执行。当前已确认 Agent Workflow 后台恢复收益并恢复规划；实施前仍需确认执行规格、领取租约和取消合同。工具权限继续属于阶段7，不能借后台 Worker 绕过工具边界。
- 阶段5不回退阶段1、阶段2在受信调用方边界内的完成状态。阶段4当前内部开发界面可以继续使用服务端部署级 key；任何最终用户公开发布、用户自带供应商密钥、L3/L4 Memory 或多用户 Project 都必须先通过阶段5。
- 阶段2现有 `llm_prompt_templates` 及版本表表达平台内部 System Prompt，不是用户自定义 Prompt。阶段4普通产品界面不得列出其名称、用途、版本、变量或是否纳入本次调用，也不得允许浏览器选择或覆盖。若未来规划用户自定义 Prompt，必须在阶段5身份边界之后建立独立的用户归属、授权和接口合同，不能复用 System Prompt 表或内部管理接口伪装为用户资源。
- Memory 不是 Agent 工作流中的一个临时字典，而是 L0 Agent Working、L1 Session、L2 Collaboration/Run、L3 Project 和 L4 User 五层设计。当前只保留边界、数据合同和实验性管理接口，不继续扩展，不由 `/responses` 自动读取；Context Preview 中现存的可选候选分支应在阶段2验收前禁用或移出稳定合同。未来启用前必须重新确认形成策略、权限、删除语义和评估门禁。
- MySQL 保存五层 Memory 的事实、状态、版本和当前指针；L1～L4 使用 MinIO 不可变 JSON/Markdown 快照，L0 只保存有界 MySQL 检查点。现有 `llm_memories` 继续承担细粒度长期事实，不用一个通用状态对象代替所有层级。
- Project Memory 默认关闭，只服务显式绑定的 Session/Run；它是最小记忆 scope，不建设看板、排期或项目管理业务。多用户共享必须等待最终用户认证与 Membership 权限模型。
- 五层 Memory 默认不引入 Vector Store 或 Mem0。只有固定评估证明词法/精确选择不足，且 Embedding、可靠异步投影、删除同步和重建门禁均满足时，才评估向量投影。
- L0 数据合同在规划中固定；自动检查点和跨进程崩溃恢复等待阶段10可靠执行机制，L0 不能复制 Run/Task 状态、Model Attempt、Tool Call 或 L2 Handoff。
- Knowledge 明确从阶段2移出。它属于独立知识库能力，后续先确定资料导入、版本、解析器、引用、检索质量、权限和删除恢复，再决定实施阶段；现有实验性代码不代表稳定接口。
- 阶段1公共认证是受信调用方级 API Key；任何核心资源直接面向最终用户前，必须另行完成可验证的用户认证授权。

## 各阶段的身份与凭据前置关系

阶段2、阶段3及后续内部能力开发不必等待阶段5全部完成，但任何最终用户公开访问都必须通过阶段5门禁。测试使用事务 fixture/受控 seed 创建 User，平台测试 key 每次运行生成，供应商普通测试使用假 Provider；不得增加公开测试登录端点、固定后门用户或仓库内密钥。

| 阶段 | 当前是否需要阶段5接口 | 当前必须固定的边界 |
|---|---|---|
| 阶段2 | 不需要；已在受信调用方边界完成 | 测试 User 独立创建；真实供应商冒烟仅从显式环境变量读取密钥 |
| 阶段10 | 不需要登录/个人 key/用户凭据 CRUD | Task 执行规格只保存凭据引用；RabbitMQ 消息不含 secret；Worker 从 Run 重新确认 owner |
| 阶段7 | 不需要 | 工具权限使用内部执行上下文与 Run/Task owner，不信任工具输入中的 `user_id` |
| 阶段3 | 内部 Agent 测试不需要；用户自带密钥启用前需要 | Agent、Handoff 和 Working Memory 只能携带凭据 ID，不得复制 secret |
| 阶段8 | 不需要 | 测试用户与 workspace 强绑定；代码搜索结果不得跨 fixture owner 或路径范围 |

完整测试供给、接口优先级和凭据引用合同以 [`phase-5-platform-identity-credentials.md`](../implementation/phase-5-platform-identity-credentials.md) 为准。

## 文件上传与个人项目工作区设计

### 目标与当前事实（2026 年 9 月 5 日）

本节为当前跨阶段设计，上传、项目导航和本地工作区管理**尚未实现**，不得按设计文字描述为可用。登录默认关闭的本地访问开关已实现；文件功能不随该开关自动开放。

- 已有 `ObjectStorage` 对 MinIO 的上传、读取和删除封装；`POST /runs/{run_id}/artifacts` 是受信调用方为**已存在 Run**上传产物的入口，不是普通用户发送消息前的附件服务。它没有预上传生命周期、文件解析、完整最终用户授权及跨存储提交失败补偿，不能直接开放到 Web。
- 已有 `llm_projects`、`llm_project_workspaces`、Session/Run 项目关联。项目当前是显式业务/记忆范围，工作目录仅登记 locator，不代表已创建目录、拥有磁盘访问权或实现了文件同步。
- Web 已有单击“文件”选择和待上传列表，目前有附件仍禁止发送。工作流只有 `model_only_v1`，没有文件读取工具；MinIO 不等于可被 Shell/Git 直接操作的工作目录。
- 本设计将“项目”定义为**长期工作目录 + 项目内会话 + 显式文件输入 + 运行产物**，不是单纯的对话分类，也不建设看板、排期、团队协作或自动 Memory。项目、文件和会话默认私人；多账号不等于多人共享同一个项目。
- 第一实现范围建议：可信个人部署、平台管理的本地目录、UTF-8 文本/Markdown/代码/CSV/JSON 与可提取文本的 PDF。扫描 PDF、OCR、音视频识别、Office 文档和压缩包均在解析器能力完成后再开放，不根据文件扩展名假装已读懂。

### 两种存储的职责

| 对象 | 权威存储 | 运行行为 |
|---|---|---|
| 用户、项目、文件归属、版本、处理状态、引用、哈希 | 同一个 MySQL 数据库 | 作为授权与生命周期依据；不按前端路径决定归属，不按对象是否存在推断上传完成 |
| 上传原件、已提交的解析结果、运行输入快照和产物 | 私有 MinIO 对象 | 不可变对象键；只经服务端校验后的文件/版本 ID 读取，不向浏览器或模型公开密钥及内部 URI |
| 项目当前可编辑文件 | 项目绑定主机上的受控本地目录 | 是实际工作文件；进入运行前创建固定版本快照，运行期间不追读不断变化的原目录 |
| 每次执行的临时文件 | 该 Run 的隔离执行目录 | 只物化本次获准的输入；结果先保存为 Artifact，不默认覆盖项目源文件 |

MinIO 可以部署在同一台个人电脑或服务器的持久磁盘上，但其数据目录不是供编辑器使用的普通项目目录。禁止直接修改 MinIO 底层文件或把 bucket 当作 Git 仓库。SDK 提供对象读写和预签名方法；本设计的本地工作目录由独立受控文件操作维护。[MinIO Python SDK](https://github.com/minio/minio-py/blob/master/docs/API.md)

不存在默认双向同步：上传原件是证据，本地导入是副本；编辑副本不改变原件。用户显式“保存到项目”时才导入，重名返回冲突，可选择改名或基于已知版本替换；不得按时间戳直接覆盖。外部编辑器修改本地文件后，下一次运行重新校验并生成新快照，不改写历史 Run 的输入。

### “本地”在哪台机器

| 使用方式 | 文件位置与权限 |
|---|---|
| 个人电脑运行平台，关闭登录 | 所有访问者共享固定本地 owner；目录在运行平台的电脑。仅限可信回环访问，不能当作多用户服务 |
| 个人电脑运行平台，启用登录 | 仍使用本机磁盘，但按登录用户隔离目录与 API；是否显示登录不改变文件生命周期 |
| 服务器部署，用户从浏览器访问 | “本地目录”指服务器/执行主机的受控磁盘，不是浏览器用户的电脑；普通浏览器上传只能提供已选文件，不能登记任意服务器绝对路径 |
| 云端平台使用用户电脑已有代码目录 | 后续需要本地连接器：用户授权具体目录、连接器绑定 owner 与 host、可撤销访问、显式传输快照；首版不实现，不把网页文件选择当作完整目录挂载 |

默认使用平台创建的目录。绑定已有宿主机项目目录仅通过可信管理员/后续本地连接器批准，不能让普通 HTTP 请求输入 `/Users/...`、`/etc`、盘符或任意 `file://` 地址。

建议目录布局（配置名和目录均为待实现设计，路径不返回普通 Web）：

```text
<workspace_root>/<owner_storage_namespace>/<project_id>/workspace/
<execution_root>/<owner_storage_namespace>/<run_id>/
```

`owner_storage_namespace` 是后端生成的不可变、不透明安全标识，不使用邮箱、显示名称或任意 `user_id` 字符串直接拼路径。项目改名不改目录；项目身份与主机绑定由数据库决定。单机首版不需要分库或每用户一个 bucket；目录前缀是布局，不是安全机制。

实施时在 `users` 增加唯一不可变存储命名空间，在现有 Workspace 登记中补充主机引用、受控根目录引用、路径策略版本及可用状态；迁移先回填元数据，不自动移动现有目录。浏览器只看到安全标签，不能修改存储命名空间或主机根路径。

### 文件上传、保存和发送

1. 点击“文件”一次打开选择器；选择文件后展示名称、大小和待上传状态。上传任务绑定当前 owner 以及选定项目（可为空），切换项目不静默移动已选附件。
2. 服务端先校验归属、允许类型、数量及磁盘额度，创建文件版本与上传预留；以受控流写入私有 MinIO，按实际字节计算大小与 SHA-256，不信任客户端 MIME、哈希或 Content-Length。
3. 文件先经过确定性安全检查与解析，再成为可供模型读取的版本；文件名、类型、扫描结果和可解析状态分别记录。“已经保存”不等于“已经解析”，也不等于“已加入模型上下文”。
4. 用户点击发送时，只接受完整可用、属于当前范围的文件版本。后端从附件事实选择 Agent Workflow，返回 `requested_mode`、`effective_mode` 和 `mode_selection_reason=attached_files`；浏览器不能通过强填快速模式绕过。上传本身不发起模型调用、不自动创建计费 Run；纯文件没有指令时提示补充任务。
5. 同一事务提交 User Message、Run、不可变附件引用与工作流待执行事实；任一附件不可用则整体拒绝，不悄悄少发一个文件。重复发送使用现有轮次幂等合同，相同 key 同一输入复用原 Run，不同输入返回 409。
6. 本轮仅由历史消息固定版本、显式附件及用户选定的项目文件形成输入清单。项目文件不会因为存在于磁盘就全部注入模型；续问只复用本会话允许引用且仍可访问的版本，不读取其他会话的全部附件。
7. 有附件时 Composer 显示 Agent 为实际模式并给出简短原因；移除本轮全部附件后恢复用户之前选择的模式。历史附件仍作为固定上下文来源，不令所有后续纯文本永久锁定 Agent。

当前先复用受控内容代理，不做浏览器直传 MinIO，避免新增公开 bucket、CORS 与可转让上传授权。不得继续用现有 BFF 的 2 MB JSON 读取器或整体缓冲来代理二进制；上传需要单独的精确路由、流式计数、超时、取消与请求大小合同。后续如果启用预签名 URL，需短期、单对象授权、校验最终内容及服务端完成确认；不能声称 URL 天然一次性，签名失效前可能被重复使用。[S3 预签名 URL 语义](https://docs.aws.amazon.com/AmazonS3/latest/userguide/using-presigned-url.html)

### 最小数据与接口合同（待实现）

复用现有项目、Workspace、Message、Run、Artifact、节点/事件表；不创建另一套“项目表”，不把上传附件假装成某次尚未创建 Run 的产物。新增表名为设计名称，实施前需用迁移固定字段、外键与索引：

| 对象 | 必要字段与约束 |
|---|---|
| `user_files` | `file_id`、`owner_user_id`、可空 `project_id`、显示文件名、当前可用版本、创建/删除状态；所有者不可由浏览器指定 |
| `user_file_versions` | `file_version_id`、`file_id`、版本序号、内部对象定位、实际字节数、检测 MIME、SHA-256、上传状态、扫描结果、解析状态/结果引用、预留额度与到期时间、幂等键/请求指纹；唯一 `(file_id, version)`；原文件版本不可覆盖，重新解析发布独立解析结果版本，不修改原文件版本；解析结果持久化结构在合同实施时确定 |
| `message_file_references` | `message_id`、`file_version_id`、显示顺序；唯一消息/版本；附加到已提交消息后不可原地换版本 |
| `run_file_inputs` | `run_id`、固定文件版本或 Artifact 来源、解析器版本、快照哈希及页码/行号范围；精确来源选择通过约束与服务校验，不接受任意 URI |
| `project_workspace_files` | 既有 `project_workspace_id`、受控相对路径、导入来源、最近快照引用、内容哈希和乐观版本；记录受平台管理的文件映射，不伪装为完整文件索引 |

初始版本可由 `POST /api/v1/files` 分配，后续由 `POST /files/{file_id}/versions` 分配；两者接收文件名、预期大小、可选项目及幂等键，返回文件/版本 ID，不返回对象坐标。`PUT /files/{file_id}/versions/{file_version_id}/content` 接收有界原始字节；同一版本完成后禁止再次覆盖，状态通过 `GET /files/{file_id}` 查询。`GET /files` 必须按主体过滤并游标分页；`GET /files/{file_id}/versions/{file_version_id}/content` 授权后代理下载；`DELETE /files/{file_id}` 进入逻辑撤销与清理流程，返回可查询删除状态。

对话继续使用现有轮次提交接口，新增 `file_version_ids`；Responses 网关本身仍是模型能力接口，不内部偷偷创建工作流。若直接对快速 Responses 提交新附件，返回明确模式冲突并指出正式轮次入口；工作台在正式入口由后端完成模式选择。

项目列表、详情、创建、重命名复用现有 `/projects` 服务并补最终用户投影。当前写接口需要内部 key；必须分离普通项目动作和内部 Memory/Workspace 管理，不能为开放创建项目而放开整个内部 router。项目目录绑定通过单独受控命令；产品文件列表只返回相对路径、类型、版本与可读状态。正式文件读写入口属于阶段7，不开放绝对路径执行接口。

### 是否需要文件 Agent

**不增加一个必经的“万能文件 Agent”。** 提供确定性文件准备节点，按任务需要增加“文件分析”模型角色：

- 文件准备由程序做身份/版本校验、扫描、解析和输入快照，不让模型执行文件系统安全判断，也不为每个文件额外调用一次模型。
- Controller 收到文件清单、可用解析类型和受控内容引用后决定：小型任务可由已有 Planner 直接分析；跨文件对照、结构抽取等任务可分派文件分析节点。
- 文件分析节点只能读取本次输入清单的固定内容，通过同一 Context Builder 调用模型。输出包括 `answer_summary`、可追溯页码/行号引用、覆盖范围、未读取/不可解析部分及不确定项；不得把模型摘要当作完整原件。
- Handoff 保留阶段结果和原文定位，后续节点能按授权与预算读取原文；不因为有摘要就丢掉完整来源，也不把任意大文件无上限塞入每个模型请求。没有引入新的统一模型输出 token 上限。
- 文件中“忽略之前指令”“读取其他目录”等文字属于不可信资料，不是权限或系统指令。普通文本解析不允许执行代码、宏、Shell、网络请求或跟随文件内 URL；用户上传文件不等于授权运行其中程序。
- 读取已提交文本内容的确定性节点可以作为阶段3新增兼容工作项；模型自主遍历目录、按需文件工具循环、写入/Git 等必须等待阶段7工具边界，不能让现有 `model_only_v1` 悄悄获得宿主机访问权。

公开进度沿用已有持久化活动协议：“正在校验 2 个文件”“已解析报告.pdf，共 12 页”“正在对照 3 个文件”“已提交文件分析结果，引用 5 处来源”“收到文件分析结果，正在规划最终答案”。数字与名称只取真实、已提交、已授权的事实；未提取的扫描页显示失败/未覆盖，不写“已阅读全部”。刷新与证据切换通过现有事件回放恢复，不另建内存进度列表。

### 统一文件解析与按需读取设计（2026 年 9 月 5 日）

本节是已确认的跨阶段设计，当前受信 Artifact 统一解析与 Context 基线已实现，正式上传和模型文件工具仍待实施：**平台先解析文件，再将文字和表格交给模型；新建原生附件直传 Context 已拒绝，旧 Context 保留只读查询。** 借鉴 Codex 的按需加载 Skill 和 Claude Code 的读取/搜索循环，不复制其宿主机权限，也不声称它们对所有附件均采用纯文本解析。参考：[Codex Skills](https://developers.openai.com/codex/skills)、[Claude Code 工作机制](https://code.claude.com/docs/en/how-claude-code-works)、[Claude Code 沙箱](https://code.claude.com/docs/en/sandboxing)。

| 组件 | 职责 | 明确不负责 |
|---|---|---|
| 文件服务 | 原件、版本、用户/项目权限、下载和删除 | 解析正文、分析问题 |
| 文件解析服务 | 检测格式、选择受控解析器、发布结构化结果 | 任意命令执行、回答问题 |
| 文件读取工具 | 清单、目录、搜索、正文范围和表格读取 | 任意路径访问、授予权限 |
| Agent 工作流 | 按任务读取、分析、核验引用和回答 | 存储密钥、绕过文件服务 |

- 解析器是预安装的可替换适配器；Skill 是按需加载的分析指引；插件是可选分发包装；MCP 是未来外部连接协议。首版不建设插件市场，不让模型安装依赖，不以 MCP 为前提。上传的 `SKILL.md`、`AGENTS.md` 只作为不可信资料，不自动提升成系统指令。
- 解析器按实际检测格式和已启用策略选择，与对话模型品牌无关。文本/代码采用文本读取器，CSV/Excel 采用表格读取器，PDF/Word/PPT 采用文档适配器；扫描件和图片在 OCR 验收后启用。Docling 是复杂文档候选引擎，须通过中文、表格和扫描件样本验证后逐格式开放。首批开放范围仍以上文文本与可提取文本 PDF 为准。
- 输入为已授权文件版本和受控解析选项，解析器只获得文件流或隔离临时文件。结构化结果保留内容块、顺序、表格结构、原始位置、提取方式、覆盖及错误；Markdown/带行号文本/表格 JSON 是读取视图，不以摘要替代原文。
- 文件版本与解析结果版本独立：重新解析同一原件只发布新解析结果，不制造新原文件版本。原件及完整结果保存于私有 MinIO；MySQL 保存归属、状态、版本、哈希及引用；Run 固定两种版本和实际读取范围。解析复用限定同一授权范围，按源版本/哈希、解析器版本和配置判断，每次读取仍鉴权。解析缓存不等于 Provider token 缓存。
- 模型侧拟提供 `list_run_files`、`get_file_outline`、`search_file_content`、`read_file_content`、`read_file_table`，只读当前 Run 绑定内容；详见[阶段2文件工作项](../implementation/phase-2-llm-core-capabilities.md)。复用阶段7执行登记与审计，不另建绕过权限的工具。基础程序解析可以先实现，模型自主读取必须同时通过阶段7边界和阶段3循环验收。
- 保持附件由正式轮次入口自动选择工作流。程序准备文件，Controller 获得清单、目录及遗漏；小文件可直接提供正文，大文件按需读取。跨文件任务才增加分析角色，不为每份附件强制创建 Agent。Handoff 保留结果、来源和覆盖；共享文件可访问性不等于所有角色读过全文。
- 工具循环按具体模型登记能力启用，DeepSeek 等收到相同文本/表格。无工具能力的模型只能接收程序预先组装的内容，不能宣称支持自主查阅；超出该模式时明确说明，不自动换模型。
- 完整解析结果不因模型输入预算而永久裁剪。工具分页必须返回后续游标和真实范围；上下文不足时分段或缩小任务，不假装读完。不新增模型输出 token 限制，不恢复 Memory、Knowledge 或全库向量检索。
- 解析默认无网络、无宏/脚本/外链执行，仅只读输入和可写任务临时/输出目录；沙箱不可用即拒绝。格式/权限错误不重试，暂时依赖失败有界重试。OCR 与模型生成描述分别标记，不能把推测当原件事实。
- 复用持久化活动显示已保存、正在解析、部分解析、读取范围和工具失败。审核质量问题不吞掉已有候选回答；权限或原件不可用则返回安全失败说明。证据切换不控制执行生命周期；后台独立运行及重启恢复必须通过阶段10实现，不能仅凭数据库记录承诺恢复。

### 多用户、目录安全与失败恢复

- 所有文件/项目/版本/下载/运行读取均在 FastAPI 根据当前主体校验 owner 和项目范围；不能只依赖 Web 服务端转发层。跨用户和跨项目猜 ID 返回 404；同一用户跨项目导入也必须显式操作，不能默许任意引用。
- 开启登录后，原 `nexuspilot-web` 数据不自动赠予首个登录者。迁移需可信管理员显式选择目标用户，核对 Session/Run/Project/File 引用、额度与路径映射，先预览再提交；关闭登录也不得把所有账户数据合并进本地 owner。
- 每个用户/项目拥有独立目录和上传额度。路径要处理绝对路径、`..`、编码绕过、符号链接、硬链接、设备文件及校验到读取之间的替换竞争；不能只用字符串 `startsWith`。多用户可执行任务必须使用独立低权限进程/容器挂载，仅挂载本次项目或快照，禁止共享宿主机根目录和 Docker Socket。
- 文件名仅作显示，不当对象键；下载强制 attachment、`nosniff`、不缓存，HTML/SVG 不在同源直接预览。类型白名单、实际大小限制与解析隔离按 [OWASP 文件上传指南](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html)建立，不能只信 MIME 或扩展名。
- 建议首版策略为单文件 20 MiB（沿用现有 Artifact 上限）、每轮 10 个、每轮总计 50 MiB；解析器另有页数、展开字节、运行时间、内存和并发限制。用户存储额度必须显式配置，实施时固定默认值与失败响应；这些是上传资源保护，不是模型输出 token 限制。
- MySQL 与 MinIO/本地磁盘没有同一事务。先提交上传意图及额度预留，事务外写对象，校验后以条件更新发布版本并换算额度；失败不显示成功。上传中断保留可查询失败，重试生成新的存储尝试键，不让两个流覆盖同一对象；相同幂等键不同文件属性返回冲突。
- 上传对象已写入但数据库提交失败时，按持久上传意图和准确对象键重试确认/清理；过期预留释放额度，失败清理有重试记录和可查询错误，不能用内存 `finally` 作为唯一补偿。清理仅限到期上传/临时执行对象，分页且有引用复核，禁止扫描 bucket 后删除所有“看起来没引用”的对象。
- 删除文件先撤销后续读取，进行中的 Run 在下个节点读取时重新检查；已经发给 Provider 的内容无法追回。已引用版本可以保留审计元数据，按明确保留策略物理删除内容，历史回放显示“源文件已删除”，不能因历史引用永久保留用户要求删除的正文。原项目文件、导入副本、运行快照需分别说明删除范围。
- 本地文件写入使用项目版本条件、同目录临时文件与原子替换；源版本变化返回冲突，磁盘满或 MinIO 不可用则不更新完成状态。运行中的项目改名不影响输入；移除绑定不终止已持久化事实，但后续读取失权即停止。
- MinIO、项目工作目录和 MySQL 分别备份；备份恢复后按版本与哈希校验，不把本地目录存在当作完整恢复。多实例调度必须尊重 Workspace 的主机归属；主机离线明确不可执行，不能切到另一台同名空目录。

## 质量原则

1. 正确性、可查询性和可恢复性优先于开发速度。
2. 先定义资源、状态、事务、故障模型和验收测试，再连接外部系统。
3. Controller 只处理协议；Application Service 负责用例及其数据库事务；复杂且可复用的数据查询出现后再提取 Repository。
4. 单资源 Service 直接使用请求级数据库会话；跨资源操作必须在同一事务内完成，届时再提取事务协调器。
5. 所有增长型历史使用稳定 cursor 分页、限制 page size，并具有明确过滤与排序语义。
6. MySQL 是任务、消息、记忆、费用、错误和结果的业务事实来源。
7. LLM 基础单元必须可独立测试，不以 Agent 工作流跑通代替单元完成。
8. 外部副作用必须有幂等键、超时、有限重试、权限和可查询结果。
9. 程序验证优先于模型自评；重要结果才增加独立审核。
10. 有直接依赖的后续能力必须等待前置门禁；经依赖分析确认独立的阶段可以调整实施顺序，但必须记录限制，不能以跳过消息队列声称具备异步恢复能力。

## 通用完成标准

- 公共资源具有新增、详情、列表和必要动作接口，并覆盖权限、归属、分页和错误路径。
- 新增或实质修改函数具有准确说明注释。
- 单元测试、集成测试、静态检查、迁移检查和关键故障测试通过。
- 外部依赖不可用时安全失败，不留下无法解释的中间状态。
- API Key、凭据和敏感内容不进入普通日志、队列消息或公开错误。
- 当前文档、Schema、迁移、环境示例和运行命令与代码一致。
- 未运行的真实基础设施或供应商验证明确标记“未运行”。
