## 本次整体规划决定

新方向不是为“通读、检索、计算、写作”各建一条专用流水线，而是固定授权执行、持续观察、历史管理、状态和记录机制，由模型根据目标与结果选择步骤。规划、Worker、Handoff、确定性验证、Reviewer 和汇总保留为可组合职责，不要求每个任务经过全部角色。三种既有审核策略与角色模型绑定继续有效，免独立审核不免权限和结果检查。

**保留：** Gateway/Provider 目录与续接、Run/Attempt/Tool Call 记账、MinIO 正文与文件快照、工具目录/搜索/读取、来源鉴权、历史节点/事件/取消和前端恢复。**调整：** 两种模式共享循环机制、上下文投影、工作记录、后端来源映射、按实际活动展示。**新执行方式替换：** 所有任务必经固定节点链、Worker/最终答案必须生成复杂嵌套 JSON。旧版本保持原语义和回放，新策略/输出版本登记前不改变旧记录。

最新反证：2026-10-18 完整 Strata PDF 运行 `4823b961-d271-4b98-b557-1c51321a899a` 在 Worker 输出及有限修正后失败，无最终答案；7 次 SSE/适配器/保存正文一致，非法 JSON 已存在于供应商返回内容。不能认定是平台丢末尾字符，也不能证明长上下文是唯一原因。旧受控样例成功与本次失败并存，详见[验证记录](../implementation/strata-long-files-verification-20261018.md#完整-agent-工作流逐调用-sse-与保存结果对照)。

### 两种存储的职责

| 对象 | 权威存储 | 运行行为 |
|---|---|---|
| 用户、项目、文件归属、版本、处理状态、引用、哈希 | 同一个 MySQL 数据库 | 作为授权与生命周期依据；不按前端路径决定归属，不按对象是否存在推断上传完成 |
| 上传原件、已提交的解析结果、运行输入快照和产物 | 私有 MinIO 对象 | 不可变对象键；只经服务端校验后的文件/版本 ID 读取，不向浏览器或模型公开密钥及内部 URI |
| 项目当前可编辑文件 | 项目绑定主机上的受控本地目录 | 是实际工作文件；进入运行前创建固定版本快照，运行期间不追读不断变化的原目录 |
| 每次执行的临时文件 | 该 Run 的隔离执行目录 | 只物化本次获准的输入；结果先保存为 Artifact，不默认覆盖项目源文件 |

MinIO 可以部署在同一台个人电脑或服务器的持久磁盘上，但其数据目录不是供编辑器使用的普通项目目录。禁止直接修改 MinIO 底层文件或把 bucket 当作 Git 仓库。SDK 提供对象读写和预签名方法；本设计的本地工作目录由独立受控文件操作维护。[MinIO Python SDK](https://github.com/minio/minio-py/blob/master/docs/API.md)

不存在默认双向同步：上传原件是证据，本地导入是副本；编辑副本不改变原件。用户显式“保存到项目”时才导入，重名返回冲突，可选择改名或基于已知版本替换；不得按时间戳直接覆盖。外部编辑器修改本地文件后，下一次运行重新校验并生成新快照，不改写历史 Run 的输入。

### “本地”在哪台机器

| 使用方式 | 文件位置与权限 |
|---|---|
| 个人电脑运行平台，关闭登录 | 所有访问者共享固定本地 owner；目录在运行平台的电脑。仅限可信回环访问，不能当作多用户服务 |
| 个人电脑运行平台，启用登录 | 仍使用本机磁盘，但按登录用户隔离目录与 API；是否显示登录不改变文件生命周期 |
| 服务器部署，用户从浏览器访问 | “本地目录”指服务器/执行主机的受控磁盘，不是浏览器用户的电脑；普通浏览器上传只能提供已选文件，不能登记任意服务器绝对路径 |
| 云端平台使用用户电脑已有代码目录 | 后续需要本地连接器：用户授权具体目录、连接器绑定 owner 与 host、可撤销访问、显式传输快照；首版不实现，不把网页文件选择当作完整目录挂载 |

默认使用平台创建的目录。绑定已有宿主机项目目录仅通过可信管理员/后续本地连接器批准，不能让普通 HTTP 请求输入 `/Users/...`、`/etc`、盘符或任意 `file://` 地址。

建议目录布局（配置名和目录均为待实现设计，路径不返回普通 Web）：

```text
<workspace_root>/<owner_storage_namespace>/<project_id>/workspace/
<execution_root>/<owner_storage_namespace>/<run_id>/
```

`owner_storage_namespace` 是后端生成的不可变、不透明安全标识，不使用邮箱、显示名称或任意 `user_id` 字符串直接拼路径。项目改名不改目录；项目身份与主机绑定由数据库决定。单机首版不需要分库或每用户一个 bucket；目录前缀是布局，不是安全机制。

实施时在 `users` 增加唯一不可变存储命名空间，在现有 Workspace 登记中补充主机引用、受控根目录引用、路径策略版本及可用状态；迁移先回填元数据，不自动移动现有目录。浏览器只看到安全标签，不能修改存储命名空间或主机根路径。

### 文件上传、保存和发送

以下是逻辑版本和项目文件的后续目标；基础上传已有实现，新增行为需独立迁移、兼容与产品验收。执行模式由用户选择，后端根据模式、附件事实和权限配置可用工具，不要求专用 File Agent。

1. 点击“文件”一次打开选择器；选择文件后展示名称、大小和待上传状态。上传任务绑定当前 owner 以及选定项目（可为空），切换项目不静默移动已选附件。
2. 服务端先校验归属、允许类型、数量及磁盘额度，创建文件版本与上传预留；以受控流写入私有 MinIO，按实际字节计算大小与 SHA-256，不信任客户端 MIME、哈希或 Content-Length。
3. 文件先经过确定性安全检查与解析，再成为可供模型读取的版本；文件名、类型、扫描结果和可解析状态分别记录。“已经保存”不等于“已经解析”，也不等于“已加入模型上下文”。
4. 用户点击发送时，只接受完整可用、属于当前范围的文件版本。保留用户选择的快速回复／Agent 模式，后端校验附件权限并选择该模式可用的工具配置；不新增自动模式切换字段，不把快速回复当作绕过权限。上传本身不发起模型调用、不自动创建计费 Run；纯文件没有指令时提示补充任务。
5. 目标是同一事务提交 User Message、Run、不可变附件引用与工作流待执行事实；任一附件不可用则整体拒绝。当前轮次已原子绑定 `file_ids`，独立后台待执行事实尚未实现。增加逻辑版本后需将固定版本纳入输入指纹，保持同 key 同输入复用、不同输入返回 409。
6. 本轮仅由历史消息固定版本、显式附件及用户选定的项目文件形成输入清单。项目文件不会因为存在于磁盘就全部注入模型；续问只复用本会话允许引用且仍可访问的版本，不读取其他会话的全部附件。
7. Composer 始终显示用户实际选择的模式及附件状态；添加或移除附件都不偷偷切换模式。历史附件按授权和固定来源规则读取，不令后续纯文本永久锁定 Agent。

当前先复用受控内容代理，不做浏览器直传 MinIO，避免新增公开 bucket、CORS 与可转让上传授权。不得继续用现有 BFF 的 2 MB JSON 读取器或整体缓冲来代理二进制；上传需要单独的精确路由、流式计数、超时、取消与请求大小合同。后续如果启用预签名 URL，需短期、单对象授权、校验最终内容及服务端完成确认；不能声称 URL 天然一次性，签名失效前可能被重复使用。[S3 预签名 URL 语义](https://docs.aws.amazon.com/AmazonS3/latest/userguide/using-presigned-url.html)

| `user_file_versions` | `file_version_id`、`file_id`、版本序号、内部对象定位、实际字节数、检测 MIME、SHA-256、上传状态、扫描结果、解析状态/结果引用、预留额度与到期时间、幂等键/请求指纹；唯一 `(file_id, version)`；原文件版本不可覆盖，重新解析发布独立解析结果版本，不修改原文件版本；解析结果持久化结构在合同实施时确定 |

| `project_workspace_files` | 既有 `project_workspace_id`、受控相对路径、导入来源、最近快照引用、内容哈希和乐观版本；记录受平台管理的文件映射，不伪装为完整文件索引 |

初始版本可由 `POST /api/v1/files` 分配，后续由 `POST /files/{file_id}/versions` 分配；两者接收文件名、预期大小、可选项目及幂等键，返回文件/版本 ID，不返回对象坐标。`PUT /files/{file_id}/versions/{file_version_id}/content` 接收有界原始字节；同一版本完成后禁止再次覆盖，状态通过 `GET /files/{file_id}` 查询。`GET /files` 必须按主体过滤并游标分页；`GET /files/{file_id}/versions/{file_version_id}/content` 授权后代理下载；`DELETE /files/{file_id}` 进入逻辑撤销与清理流程，返回可查询删除状态。

对话继续使用现有轮次提交接口，后续增加 `file_version_ids`；Responses 网关不内部偷偷创建工作流。新附件先经正式上传和轮次绑定，未绑定、失权或非法版本按输入／资源错误拒绝，不称为“快速模式冲突”。快速回复继续走自己的工具循环，Agent 走工作流，两者使用同一附件权限规则。

### 多用户、目录安全与失败恢复

- 所有文件/项目/版本/下载/运行读取均在 FastAPI 根据当前主体校验 owner 和项目范围；不能只依赖 Web 服务端转发层。跨用户和跨项目猜 ID 返回 404；同一用户跨项目导入也必须显式操作，不能默许任意引用。
- 开启登录后，原 `nexuspilot-web` 数据不自动赠予首个登录者。迁移需可信管理员显式选择目标用户，核对 Session/Run/Project/File 引用、额度与路径映射，先预览再提交；关闭登录也不得把所有账户数据合并进本地 owner。
- 每个用户/项目拥有独立目录和上传额度。路径要处理绝对路径、`..`、编码绕过、符号链接、硬链接、设备文件及校验到读取之间的替换竞争；不能只用字符串 `startsWith`。多用户可执行任务必须使用独立低权限进程/容器挂载，仅挂载本次项目或快照，禁止共享宿主机根目录和 Docker Socket。
- 文件名仅作显示，不当对象键；下载强制 attachment、`nosniff`、不缓存，HTML/SVG 不在同源直接预览。类型白名单、实际大小限制与解析隔离按 [OWASP 文件上传指南](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html)建立，不能只信 MIME 或扩展名。
- 当前正式上传单文件上限已调整为 20 MiB，其他实际上传/解析资源限制由阶段2及阶段7维护；旧 1 MiB 不再作为当前要求。上传可保存不代表模型已阅读全文；这些是文件资源限制，不是模型输出 token 上限。
- MySQL 与 MinIO/本地磁盘没有同一事务。先提交上传意图及额度预留，事务外写对象，校验后以条件更新发布版本并换算额度；失败不显示成功。上传中断保留可查询失败，重试生成新的存储尝试键，不让两个流覆盖同一对象；相同幂等键不同文件属性返回冲突。
- 上传对象已写入但数据库提交失败时，按持久上传意图和准确对象键重试确认/清理；过期预留释放额度，失败清理有重试记录和可查询错误，不能用内存 `finally` 作为唯一补偿。清理仅限到期上传/临时执行对象，分页且有引用复核，禁止扫描 bucket 后删除所有“看起来没引用”的对象。
- 当前删除撤销后续读取并清理原件/解析对象，不删除已保存回答及 Context 摘录；已经发给 Provider 的内容无法追回。项目源文件、导入副本、运行快照需分别定义删除范围。若增加删除历史正文功能，必须单独设计保留/引用与迁移，不能静默改变现有删除承诺。
- 本地文件写入使用项目版本条件、同目录临时文件与原子替换；源版本变化返回冲突，磁盘满或 MinIO 不可用则不更新完成状态。运行中的项目改名不影响输入；移除绑定不终止已持久化事实，但后续读取失权即停止。
- MinIO、项目工作目录和 MySQL 分别备份；备份恢复后按版本与哈希校验，不把本地目录存在当作完整恢复。多实例调度必须尊重 Workspace 的主机归属；主机离线明确不可执行，不能切到另一台同名空目录。

### 工作项归属、实施顺序与验收

本设计整体属于上方“个人项目与文件能力”，不再拆成六个 Phase 的独立待办。文件归属与生命周期使用阶段2现有规则；新增项目导航、API 权限、目录导入/快照、冲突检测和页面一起验收。模型自主读取/执行归工具主计划，长解析恢复引用后台执行机制。

先有私人项目与固定输入，再开放编辑与显式输出写回；不把仅有项目元数据称为可读取目录。必须验证双用户/跨项目拒绝、上传幂等、真实存储失败补偿、删除竞争、路径/链接攻击、同名冲突、外部编辑、主机离线、部分解析、引用和刷新行为。真实 MySQL/MinIO/目录检查不能由假存储代替。

当前默认平台管理目录；用户电脑目录连接器后置。具体磁盘额度、目录保留策略、支持格式和运行镜像在实施对应工作项前固定；未授权不绑定任意宿主路径、不扫描磁盘。Office/PDF 本地与服务器事实见[解析本地实施记录](../implementation/phase-7-tool-runtime-plan.md#本地实施记录2026-年-10-月-7-日)及[服务器历史记录](../implementation/server-deployment-20261004.md)。

## 质量原则

1. 正确性、可查询性和可恢复性优先于开发速度。
2. 先定义资源、状态、事务、故障模型和验收测试，再连接外部系统。
3. Controller 只处理协议；Application Service 负责用例及其数据库事务；复杂且可复用的数据查询出现后再提取 Repository。
4. 单资源 Service 直接使用请求级数据库会话；跨资源操作必须在同一事务内完成，届时再提取事务协调器。
5. 所有增长型历史使用稳定 cursor 分页、限制 page size，并具有明确过滤与排序语义。
6. MySQL 是任务、消息、记忆、费用、错误和结果的业务事实来源。
7. LLM 基础单元必须可独立测试，不以 Agent 工作流跑通代替单元完成。
8. 外部副作用必须有幂等键、超时、有限重试、权限和可查询结果。
9. 程序验证优先于模型自评；重要结果才增加独立审核。
10. 有直接依赖的后续能力必须等待前置门禁；经依赖分析确认独立的阶段可以调整实施顺序，但必须记录限制，不能以跳过消息队列声称具备异步恢复能力。

## 通用完成标准

- 公共资源具有新增、详情、列表和必要动作接口，并覆盖权限、归属、分页和错误路径。
- 新增或实质修改函数具有准确说明注释。
- 单元测试、集成测试、静态检查、迁移检查和关键故障测试通过。
- 外部依赖不可用时安全失败，不留下无法解释的中间状态。
- API Key、凭据和敏感内容不进入普通日志、队列消息或公开错误。
- 当前文档、Schema、迁移、环境示例和运行命令与代码一致。
- 未运行的真实基础设施或供应商验证明确标记“未运行”。
